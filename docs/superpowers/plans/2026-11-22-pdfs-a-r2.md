# PDFs de los viajes a Cloudflare R2: plan de implementación

> **Para quien ejecute:** SUB-SKILL OBLIGATORIA: usa superpowers:subagent-driven-development (recomendada) o superpowers:executing-plans para implementar este plan tarea a tarea. Los pasos usan casillas (`- [ ]`).

**Objetivo:** que ningún PDF de viaje viva en Sanity ni se sirva desde `cdn.sanity.io`; cada viaje enlaza su PDF en Cloudflare R2.

**Arquitectura:** los 8 PDFs en uso pasan a un bucket R2 con dominio propio. El campo `dossier` (URL) de los 15 documentos `trip` pasa a apuntar a R2 y se retira `dossierFile`. El build lee `dossier` tal cual. Studio exige el dominio de R2 y el build rechaza cualquier enlace a archivos de Sanity.

**Tecnología:** Node `--test`, Sanity (GROQ, Studio 6.19, MCP/CLI), Cloudflare R2 (conector `/mcp` o Wrangler), Vercel.

**Spec:** `docs/superpowers/specs/2026-11-22-pdfs-a-r2-design.md`

## Restricciones globales

- Ningún PDF de viaje queda en Sanity ni se sirve desde `cdn.sanity.io`.
- La web publicada sigue funcionando durante todo el cambio: ningún enlace de descarga roto.
- No se borra nada de Sanity antes de comprobar que R2 responde y que la web ya sirve desde R2; el borrado exige confirmación aparte del usuario.
- No subir al bucket público documentos con datos personales.
- Fuera de alcance: imágenes de Sanity, subida desde Studio hacia R2, cabeceras de caché de Vercel.
- El árbol de trabajo ya tiene cambios sin commitear de otro trabajo (`scripts/render-trips.mjs`, varios `scripts/trip-*.test.mjs`, `dist/**`). Haz `git add` solo de los archivos de cada tarea. No commitees ni empujes sin que el usuario lo pida; Vercel solo despliega código empujado a `main`.
- Los tests se lanzan con `npm test` (`node --test scripts/*.test.mjs`). Pie de commit: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Decisiones que se apartan del spec (mi criterio, revisar)

- El spec dice que `httpsUrl` del build acepta solo el dominio de R2. Aquí **Studio** exige el dominio de R2 (el editor ve el error al publicar) y el **build** solo rechaza enlaces a archivos de Sanity. Así una errata de host no detiene toda la reconstrucción de la web, y los tests existentes que usan `https://example.com/...pdf` siguen valiendo.
- `scripts/update-trip-promotions.mjs` no se modifica: es un script puntual ya aplicado y su `coalesce(dossierFile.asset->url, dossier)` sigue funcionando sin el campo.
- Los PDFs se suben con `Cache-Control: public, max-age=86400`. Para sustituir un PDF se sube con un nombre nuevo (`-v2`), nunca encima.
- El spec pide actualizar también el README, pero el README no describe la subida de PDFs; solo se cambia `docs/guia-cliente.md`.

## Revisión de casos límite

- Host parecido al de R2 (`<host>.evil.com`, `https://<host>@evil.com/a.pdf`): debe rechazarse. Test en la Tarea 2.
- Pegar una URL que no es un PDF (el panel de Cloudflare, una carpeta del bucket): debe rechazarse. Test en la Tarea 2.
- Host en mayúsculas o con espacios alrededor: debe aceptarse. Test en la Tarea 2.
- Borradores que conservan `dossierFile` tras quitar el campo del schema (Studio mostraría «campo desconocido»): la Tarea 4 comprueba que no queda ninguno en `raw`.
- PDF sustituido con el mismo nombre y caché larga: el navegador mostraría el viejo. La guía (Tarea 5) manda usar un nombre nuevo, y la Tarea 1 comprueba la cabecera `cache-control`.
